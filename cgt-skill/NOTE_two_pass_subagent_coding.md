# Note — two-pass primed subagent for CGT initial coding (PROVISIONAL, not validated)

*Date: 2026-06-25. Context: SSRC output-format-bias coding. Written at June's request. Status: a promising pattern observed once; **not validated by the researcher**. Do not treat as established.*

## The problem it addresses
A context-limited but method-calibrated instance needs to offload bulk *initial* coding without reproducing the failure that derailed prior attempts: cold agents doing **deductive code-application** — matching new data to the existing codebook, imposing preconceived categories, producing ungrounded codes that dissolve on inspection. (This is exactly what memo 028 and memo 031 warn against.)

## The move (three required parts — all three, or it reverts to the failure)
1. **Full priming, not a compression.** Prime the subagent on the actual method — the cgt-skill memos (`methodological_insights` + 001/016/025/027/028/031/032) — plus the project's worked examples. A compressed "calibration block" alone is NOT enough; the memos carry the *disposition* (pattern-as-variation, openings-not-themes, negative cases, data-first emergence) that the rules only gesture at.
2. **Two passes per output, both mandatory.** (a) **Apply** an established code where the move *genuinely recurs and is grounded in this rationale's words* (defensible recurrence — fine). (b) **Emerge** — explicitly ask "what is THIS rationale doing that the existing codes do NOT capture?" and coin a grounded new code. The emergence pass is what makes pattern-matching defensible (June's framing: matching is acceptable *because* you also do the work of finding what gets missed — and that finding is where the highest-value results live, e.g. the S001 critique→knowledge-gap inversion).
3. **A verification gate held by a primed human/instance — two dimensions:**
   - **Verbatim fidelity** (mechanical, delegable to a separate checker): the rationale text the codes sit on is unaltered, correct condition. A script can do this.
   - **Grounding** (judgment, NOT delegable): does each code sit on what the rationale actually *means*? This stays with the primed reader. This is the dimension that protects against the failure mode, and it cannot be automated away.

## Why it might generalize
The failure of cold-agent CGT is (i) imposed categories, (ii) ungrounded codes. Full priming addresses the disposition; the explicit emergence pass addresses the imposition; the grounding gate addresses ungroundedness. Each failure has a named countermeasure.

## STATUS — explicitly NOT validated (read before relying on this)
In one trial: a fully-primed two-pass subagent produced verbatim-clean codes and genuine emergent finds; a *representative* grounding spot-check passed. That is **one trial + one spot-check**, not validation. The researcher has not validated the approach, and validating it is itself work that competes with doing the analysis. So:
- Do **not** scale it as trusted. Treat all subagent output as **drafts behind the grounding gate**.
- The grounding gate is non-negotiable. Without a primed reader doing it, this collapses straight back into the pattern-matching failure it was meant to avoid.
- Adopt only when the verification cost is affordable relative to the alternative (the primed instance coding directly). If the human can't afford to validate AND the verification is the whole safeguard, prefer direct coding for the load-bearing cases.
