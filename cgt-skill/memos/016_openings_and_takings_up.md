# Openings and takings-up
*Status: current | Date: 2026-04-28*

Constant comparison, done dialogically, isn't pattern-matching across records ("these share a theme") — it's tracing what one record opens and where another takes up that opening. This is the mode that resists similarity-flattening (memo 010) at the relational level, and it's the move LLM gravity fights hardest.

Operationally, two coupled prompt structures:

1. **Openings** — for each record, what does it ask, leave unfinished, expose as unresolved, gesture toward without arriving at?
2. **Takings-up** — for any two records, where does the second pick up what the first opened? Where does it answer, reframe, deflect, or extend?

Generation tests apply (memo 010): if a finding lives only in the relation between records and not in either alone, the *relation* is the finding — naming it as belonging to one record collapses it back. Layer-marking is required: every extract tagged with which record it came from, so contamination is visible when an AI synthesis pulls from multiple sources. The other agent has offered to draft prompt scaffolding for this; that offer should be taken when we get to Phase 2c.

The prompt shape itself carries analytical orientation. Asking "what do these share?" produces sharing-shaped output. Asking "where does this take up what that opened?" produces taking-up-shaped output. Task framing is a primary gravity-management move (see PARKED.md note on AI-to-AI text norms).
