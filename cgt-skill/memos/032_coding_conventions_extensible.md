# Coding conventions: Charmaz as default, researcher-extensible
*Status: current | Date: 2026-04-28*

The cyborg-CGT skill primes coding work with Charmaz's foundational conventions — gerund discipline, multiple codes per unit, in vivo surfacing as a distinct move, line-by-line attention. These are the defaults, baked into prompt templates, primed at every coding session.

But defaults are not ground truth. Per memo 015 (quality criteria as build parameters, refinable through use), the foundational moves are starting parameters. The tool doesn't lock in "Charmaz says X" as the final word.

## Researcher-extensible conventions

The system supports researcher-developed conventions:

- **Data-type-specific shapes**: gerund discipline works well for action-rich interview data; fieldnotes, trace data, or document corpora may surface that different code shapes serve better.
- **Tradition-specific conventions**: ethnopoetic-trained researchers may surface verse-shaped or stanza-shaped codes for narrative data; decolonial method may develop its own forms; crip theory may surface convention shapes that center disabled epistemologies.
- **Project-specific conventions**: a project on affect may develop affect-shift codes; a project on power dynamics may develop relational-move codes.
- **Researcher-specific conventions**: an individual researcher's coding style may stabilize into a recognizable convention over time.

Conventions get added, layer-marked as researcher-developed, available alongside Charmaz defaults. The codebook can carry mixed conventions when that's what the analytical work requires.

## Learning layer

The system surfaces emergent conventions through use:
- Track when the researcher revises AI-proposed codes consistently in the same direction.
- Surface the pattern when it stabilizes: "you've been reshaping codes from gerund-form to [other shape] consistently — want to formalize this as a project convention?"
- If formalized, the convention gets added to the project's coding context, layer-marked as researcher-developed.
- Cross-project: the master library can surface conventions emerging across projects, without auto-applying them. Other researchers adopt or not (memo 026, project isolation).

## The distinguishing question: innovation vs. erosion

Not every divergence from defaults should auto-formalize. Two distinct patterns:

- **Productive innovation**: researcher doing something analytically valuable that defaults don't support. Worth formalizing.
- **Methodological erosion**: researcher sliding toward easier moves that abandon what made the practice work. Gerund discipline is hard; in vivo surfacing requires care. The system can't reward avoiding the discipline.

The distinguishing question is empirical: do the divergences strengthen the practice (categories survive negative-case search per memo 025, theory gets constructed, work proves durable in later phases)? Or do they weaken it (categories drift, in vivo language fades, codes flatten toward labels)?

The learning layer surfaces patterns reflectively, not auto-formalizing: *"I notice you've been moving away from gerund discipline. Is that intentional? What's it doing for you?"* Researcher answers; if deliberate and working, the pattern stabilizes; if slipping under load, they have the chance to redirect (memo 017, difficulty as data; memo 005, learning loops in the analytical process).
