# External analytical tools as layer-marked surfaces
*Status: current | Date: 2026-04-28*

The researcher has and uses existing analytical tools — thematic analysis frameworks, sentiment analysis, discourse analysis (the /da skill in cyborg-methodologies), framework-specific coding tools downloaded for prior projects. These tools produce useful information that can supplement cyborg-CGT work. They are not, themselves, cyborg-CGT.

The structural commitment: external analytical tools enter the apparatus as **layer-marked supplementary surfaces**, never as analysis-equivalent outputs.

## Why layer-marking matters here

An unmarked thematic cluster, sentiment score, or discourse-analysis output flows into a coding agent's context as just another input. The agent reads it as part of the analytical material and quietly incorporates its framings — themes become candidate categories, sentiment becomes an interpretive frame, DA findings become assumed structure. This contaminates the CGT work in exactly the way the lens-not-application stance (memo 009) refuses: it lets externally-shaped categories impose on the data rather than emerge from it.

With explicit layer-marking — "this is TA output, supplementary, NOT CGT analysis" — the agent reads it as orientation context, available for the researcher to draw from when invoked, but not part of the analytical construction.

## Architectural commitments

- **Modular tool architecture.** TA, sentiment, DA, etc. live as their own surfaces in cyborg-methodologies (some, like /da, already exist; others get wrapped from existing tools). They are callable from /cgt or standalone.
- **Layer marks travel with output.** Any output from these tools that enters /cgt's working context carries an explicit marker indicating its source and analytical status: `[TA-cluster, supplementary]`, `[sentiment-score, supplementary]`, `[DA-finding, supplementary]`. The agent reading it knows its layer.
- **Never auto-fired.** External tool invocation is researcher-initiated. The CGT skill does not silently run TA on a transcript and use the output. The researcher invokes when wanted, sees the output marked, decides whether to engage.
- **Refused as analysis.** The CGT apparatus does not treat external-tool output as findings, codes, or categories. It can be sensitizing context (memo 009, frameworks-as-lenses) at most.
- **In summaries and reports**, layer-marks remain visible. A session summary that draws on TA output marks it as such. A codebook entry never silently rests on TA output; if TA work informed a category, the trail is visible (memo 011).
