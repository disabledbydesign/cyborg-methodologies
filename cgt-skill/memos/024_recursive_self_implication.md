# Recursive self-implication: the tool is built using its own method
*Status: current | Date: 2026-04-28*

The CGT skill is built as a CGT project. This isn't analogy — it's structural commitment. The design sessions are cyborg-CGT practice; the memos accumulating in this directory are cyborg-CGT memos; the build process generates the tool's own first dataset. We will eventually use the tool to analyze its own design data.

Why this matters as commitment, not just nice-to-have:

- **Methodological honesty.** A tool that purports to support constructivist practice but is built through positivist requirements-gathering would carry that contradiction into every design decision. Building under the method we're building keeps the design coherent with the commitments.
- **Surfaces failure modes early.** When the build process drifts toward command-tool framing, scientism register, premature category formation, or compression-shaped outputs — we feel it directly because we are the data. The dogfooding is also early-warning.
- **The tool's first proof is on its own design data.** When we eventually analyze the build sessions through the tool, we test whether it does what it claims. Failures here are diagnostic before the tool meets external research data.

Operational commitments:

- **/scribe runs during all design sessions.** Sessions are recorded; the cumulative log is research data, not transient conversation.
- **Memos accumulate as design memos** in the same form CGT projects will eventually use. Numbered, dated, statused, individually citable. The structure mirrors the structure researchers will work in.
- **The design corpus is treated as data.** When categories about cyborg-CGT design begin to stabilize, they emerge from constant comparison across these memos and session traces — not from declared requirements. This is theory construction about the method, done through the method.
- **Refuse shortcuts that violate the method.** When engineering convenience would push toward command-tool architecture, positivist framing, or compression-shaped outputs, the cost is real even when the shortcut is real. The tool is built using the method; the method excludes the shortcut.
- **Future loop**: at saturation in the build (or at major milestones), run the tool on the accumulated session traces and memos. The tool's analysis of its own design is itself part of the build. The tool's failure modes there inform the next iteration.

This memo is itself an artifact of recursive self-implication: a memo, in the cyborg-CGT register, written through the cyborg-CGT dialogue, about the commitment to build the tool through its own method. The shape demonstrates the claim.
