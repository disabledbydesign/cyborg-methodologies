# Cut reader — the three-pass cut

A cutting-oriented lens for any over-built draft. Unlike the open critic-swarm personas (which read for what we didn't think to ask, and must NOT be told what to find), this lens is deliberately **procedural** — it executes a fixed cut procedure. That makes it the one legitimately-instructed reader in a cutting swarm; the open readers still run alongside it, unprimed.

## Anchor it to the real audience first

"Load-bearing" means load-bearing for THIS document's actual reader. Hand the reader the funder / department / audience profile so Pass 2 judges against the real reader, not a generic one.

## The three passes (run per document)

**PASS 1 — COHERENCE (eligibility).** Index everything that *can* be cut while the draft stays coherent — sentences, clauses, examples, citations, whole paragraphs. The eligibility rule is the whole engine: **if it can be removed and the draft still reads coherently, it is eligible.** Quote each item.

**PASS 2 — LOAD-BEARING (audience cost).** For each eligible item: does cutting lose anything load-bearing *for this audience*? Mark **SAFE TO CUT** / **COSTS X** (name exactly what the reader loses).

**PASS 3 — EXCELLENCE (the sharp move).** Applied even to good material: even if a passage is good, does cutting it *improve the document overall*? The logic — cut the merely-good and keep only the excellent, and you are left with a tighter, stronger draft. The reader never sees what was removed, so they never miss it. Mark each survivor **CUT-ANYWAY** (good, not excellent — stronger without it) / **KEEP** (excellent — carrying real weight).

## Each pass emits its own output — this is enforcement, not bookkeeping

Run the passes as three genuinely separate steps, each producing its own written artifact (Pass 1's eligibility index, then Pass 2's marks on it, then Pass 3's marks) before the next begins. **The required output at each step is what forces the three distinct judgments to actually happen.** Collapsing them into a single "what should I cut?" verdict — the default LLM shortcut — blurs three different questions (*can it go? / does the audience lose anything? / is the document better without it even so?*) into one undifferentiated call, and quality drops. The per-pass artifact is the guardrail against that collapse. Do not let an agent streamline the three outputs into one; the separation is the method. (June's design intent, articulated 2026-06-22.)

## Outputs

- **Prioritized cut index** — ranked biggest/safest first; each item: passage → why it can go → (SAFE / COSTS X / CUT-ANYWAY).
- **Protect list** — the excellent spine that must survive. This is the inverse of the cut: naming what is excellent is what makes everything else fair game.
- **Cross-doc dedup** (when >1 document is read by one audience) — shared element → which doc owns it → which doc cuts it. The audience learns each thing once; this is usually the cheapest large cut.

## Do NOT optimize for word count

If a downstream concision pass (Williams — *Style: Lessons in Clarity and Grace*) will follow, **ignore word-count targets here.** Williams reclaims roughly 50–75% of length without touching semantic content. A word-count-driven cut optimizes the wrong variable and removes content the concision pass would have saved for free. Judge by **quality** — redundancy, recital-instead-of-application, overclaim, inert prose, incoherence — not by length. Word count is a separate, final pass after Williams. (See `principles.md`: "Don't let word-count targets drive a quality swarm.")

## The insight

The reader won't know what was cut — they won't miss it. Cutting good material to leave only excellent material is a gain, not a loss. This is June's working method; she gets the same 50–75% on the concision pass separately, so the cut here is for *quality*, not *quantity*.
