# Stage 0 Intake — Gap Backlog

**Surfaced 2026-06-12 (Oxford AFP application session).** Several interrelated gaps where the pipeline got deep into materials before decision-relevant facts surfaced. Captured here so they're not lost; implementation of the TO-DO items is **deferred to a focused session** (not under the Oxford deadline).

## Unifying insight

Stage 0 currently assembles source *materials for drafting* but does not run a rigorous *opportunity intake* that surfaces the decision-relevant facts — and a deliberate project-selection — **before** drafting. The fix is an **Opportunity Intake / Scoping front-end** at Stage 0 that, before any drafting, produces and surfaces to the author:
1. **Opportunity Summary** — stipend/comp amount, duration, format, time commitment, what the fellowship/role actually entails → an informed go/no-go.
2. **Eligibility** — captured and checked against the applicant (affiliation, employment, publication/grant bars) → confirmed or risk-flagged up front.
3. **Real category/priority meanings** — researched from the source (programme pages, faculty, scope), not inferred from one-line labels.
4. **Project-selection** — which of the author's projects best fits this opportunity's priorities + hard constraints; which *face* of the work the application will lead with.
5. **The full submission surface** — the posting AND the actual application form/portal — captured as the Requirements Ledger, with the PDF-vs-form division of labor made explicit.
6. **AI-can't-access handoff** — for anything behind a login (forms, portals), a defined human-in-the-loop process.

Then the existing **Stage 0b/0c** (ledger drives the draft) + **Stage 4.6** (compliance gate) follow.

## Gaps

### 1. Structured submission requirements discovered late — ✅ FIXED 2026-06-12
Stage 0 mandatory **Submission Requirements Ledger** (`APPLICATION_STRUCTURE.md`, universal) + **Stage 4.6 Requirements Compliance Gate** + Job-Search session-start re-verification (closures AND requirement changes).

### 2. Ledger must DRIVE in-scope drafting without expanding scope — ✅ REVISED 2026-08-24
Stage 0c now assigns every requirement an owner. `DRAFT` rows become Stage 1 allocation targets and Stage 2 / drafting-subagent hard constraints. `AUTHOR-HANDLED` and `PORTAL` rows remain visible through compliance but do not become prose targets. Reference lists are always author-handled; academic CVs are author-handled; required résumés enter drafting unless the author explicitly takes them over.

### 3. Opportunity terms not surfaced at intake — ⏳ TO-DO
*Oxford failure:* June invested heavily before learning the stipend is ~£2K/month (~£12K for 6 months, part-time, alongside other work). Comp / duration / format / time-commitment must be surfaced up front as part of go/no-go.
*Fix:* Stage 0 **Opportunity Summary**, surfaced to the author before drafting.

### 4. Eligibility not surfaced/confirmed at intake — ⏳ TO-DO
*Oxford failure:* "do I need an affiliation if unemployed?" surfaced mid-stream (position ended 2026-05-23). Eligibility should be captured + checked against the applicant up front.
*Fix:* Stage 0 captures eligibility, confirms the applicant meets it (or flags risk), surfaces before drafting. (Oxford answer: "otherwise professionally established" / "independent researchers" — affiliation NOT required.)

### 5. The application FORM not captured — ⏳ TO-DO
*Oxford failure:* a **14-page Microsoft Form** with substantive fields (short summary, project stage, partnerships, delivery roadmap/milestones, impact + indicators, research-priority selection, mission-alignment, length, format) was never captured. It changed the division of labor — the *form* carries milestones/impact/partnerships, so the 500-word PS PDF did **not** need them crammed in. Discovered at hour ~10.
*Fix:* Stage 0 captures the actual submission **form** (pages + questions), not just the posting. Form fields ARE requirements (into the ledger) and set the PDF-vs-form division of labor.

### 6. AI-can't-access handoff has no defined process — ⏳ TO-DO (process principle)
*June's point:* when AI cannot access something (form/portal behind login), there must be a defined handoff — **AI captures what it can, explicitly flags what it can't, and routes to the author with (a) the link, (b) drafted content ready to paste, (c) a clear "you do this part" instruction.** The author is informed and equipped, not left to discover it.
*Fix:* add an **AI-can't-access handoff** protocol to Stage 0 + Stage 4.6.

### 7. No project-selection step — ⏳ TO-DO
*Oxford failure:* nothing asked "which of June's projects best fits THIS opportunity's priorities/constraints?" Defaulted to the output-format-bias (OFB) project because it was top-of-mind. Reframe → **Philosophy to Code** was the unweighed alternative (a strong fit for *that* programme, but a different project; OFB was the better AFP fit because its empirical *finding* clears the "not early-stage" bar). PMA/RMA correctly disqualified as too early-stage.
*Fix:* a **project-selection move** at intake — lay viable projects against the opportunity's priorities + hard constraints, choose deliberately, name which face of the work leads.

### 8. Category/priority meanings inferred from labels, not researched — ⏳ TO-DO
*Oxford failure:* research-priority categories were read from one-line phrases; the author had to direct the agent to look up what they actually mean (named programmes, specific faculty, real scope). The OFB project's true home (**AI policy, law and regulation** — the *"nonmaterial AI harms"* focus, Cofone) only became clear after reading the source.
*Fix:* Stage 0 **researches what the opportunity's categories/priorities actually mean from the source** before mapping the project to them. Instance of "read the source, don't infer from the label."
